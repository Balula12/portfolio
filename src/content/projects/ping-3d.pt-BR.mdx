## Por que existe

Quis exercitar Three.js fora do contexto de React Three Fiber, escrevendo o loop de
renderização e a lógica de jogo do zero. Saiu pequeno (~25KB), mas com física básica,
detecção de colisão, sombras dinâmicas e UI sobreposta ao canvas.

## Decisões técnicas

- **Sem React** no engine — para não pagar custo de reconciliação no game loop. Mantive
  vanilla JS e mexo no DOM apenas pro placar e overlay de pause.
- **5 módulos por concern**: cena (luz, câmera, mesa), bola (física e reset), raquete
  (input e bot), placar, e o main que orquestra.
- **Sem state management** — o estado do jogo é uma struct mutável passada entre módulos,
  porque o game loop reescreve quase tudo a cada frame.

## Migração para o portfólio

No projeto original o Three.js vinha por importmap CDN. Para integrar aqui no portfólio
(Next.js 16) os imports foram trocados pelo pacote npm e o engine foi embalado num Client
Component (`PongCanvas`) que monta o canvas e inicializa tudo num `useEffect`.
