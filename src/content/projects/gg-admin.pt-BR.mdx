## Por que existe

O Firestore é ótimo para escrita transacional (alto throughput, listeners realtime), mas
ruim para queries analíticas em volumes grandes. Conforme o GG Checkout cresceu, os relatórios
ficaram lentos — agregações sobre milhões de transações em Firestore não escalam.

A solução foi separar transacional e analítico: o Firestore continua sendo a fonte de
verdade, e um pipeline de sincronização replica os dados para ClickHouse, que é otimizado
para queries OLAP. O dashboard consulta ClickHouse para todos os relatórios.

## Resultado

Dashboards que antes levavam segundos pra carregar agora respondem em milissegundos. O
ClickHouse também permite análises mais ricas (funis, cohorts, série temporal) que seriam
inviáveis em Firestore.
